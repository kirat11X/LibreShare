# CI Workflow Proposal for LibreShare

**Author:** A8 Auditor  
**Date:** 2026-11-05  
**Target:** GitHub Actions CI (`.github/workflows/ci.yml` and `.github/workflows/prototype.yml`)  
**Status:** PROPOSAL (Read-only audit & architecture recommendation; existing workflow files are unchanged)

---

## 1. Executive Summary & Audit Overview

This document reviews the current continuous integration setup in `.github/workflows/ci.yml` and `.github/workflows/prototype.yml` against the project specification (spec §14), `CLAUDE.md`, and development standards in `docs/plans/HANDOFF.md`.

### Current Workflow State
- `.github/workflows/ci.yml` currently specifies 4 top-level jobs:
  1. `core`: Monolith running workspace resolve, Flutter-import guard, `dart analyze`, `dart format`, core unit/security tests, CLI tests, and loopback smoke sequentially on Ubuntu.
  2. `detect`: Probes filesystem paths (`tools/docker/compose.yaml`, `apps/libreshare_app/pubspec.yaml`) to output boolean flags.
  3. `e2e-docker`: Multi-container integration tests using Docker Compose.
  4. `app`: Matrix job (`linux`, `apk`, `windows`, `macos`) running app tests, Linux integration tests, and release builds.
- `.github/workflows/prototype.yml` specifies on-demand / tag release builds for Linux, Android, and Windows.

## 2. Assessment of Required CI Jobs

The audit evaluated the presence of 9 core capabilities as discrete, parallelizable GitHub Actions jobs:

| Capability | Current State in `.github/workflows/ci.yml` | Discrete Job? | Notes & Gaps |
|---|---|---|---|
| **1. Format** | Embedded step in `core` job (`dart format --output=none --set-exit-if-changed .`) | **MISSING** | Runs *after* static analysis; fails silently or never runs if `dart analyze` fails first. |
| **2. Analyze** | Embedded steps in `core` (`Core must not import Flutter` + `dart analyze --fatal-infos`) | **MISSING** | Blocks downstream test execution in the same runner. |
| **3. Core tests** | Embedded step in `core` (`cd packages/libreshare_core && dart test`) | **MISSING** | Over 2,300+ tests including crypto, SAS, TLS, and protocol conformance; blocked if formatting or analysis fails. |
| **4. CLI tests** | Embedded step in `core` (`cd packages/libreshare_cli && dart test`) | **MISSING** | Runs after core tests; independent CLI tests should report separately. |
| **5. App tests** | Embedded step in `app` matrix (`cd apps/libreshare_app && flutter pub get && flutter test`) | **MISSING** | Redundantly executed 4 times (Linux, Android APK, Windows, macOS); tightly coupled with heavy compile steps. |
| **6. Loopback smoke** | Embedded step in `core` (`tools/loopback_smoke.sh 100 53400`) | **MISSING** | Lacks `LS_CI=1` env var; requires `.toolchain/` directory to exist or `LS_CI=1` to avoid sourcing dev-box paths. |
| **7. Docker e2e** | Standalone job (`e2e-docker`) | **PRESENT** | Evaluates Docker Compose topology (Alice, Bob, Carol, Tester). |
| **8. Linux build** | Embedded step in `app` matrix (`target: linux`) and in `prototype.yml` | **MISSING** as dedicated CI job | In `ci.yml`, uses raw `flutter build linux --release` rather than standardized `tools/package_prototype.sh linux`. |
| **9. Android build** | Embedded step in `app` matrix (`target: apk`) and in `prototype.yml` | **MISSING** as dedicated CI job | In `ci.yml`, produces raw `app-release.apk` rather than universal and per-ABI split APKs generated by `tools/package_prototype.sh android`. |

### Summary of Missing Discrete Jobs
- **Missing as standalone jobs:** `format`, `analyze`, `core-tests`, `cli-tests`, `app-tests`, `loopback-smoke`, `linux-build`, `android-build`.
- **Present as standalone job:** `docker-e2e` (`e2e-docker`).

## 3. Key Findings & Pipeline Risks

1. **Sequential Cascading Failures in `core`:**  
   Because format checking, static analysis, core tests, CLI tests, and loopback smoke are lumped into a single job, any minor doc lint or format issue prevents tests from running. Developers cannot see whether test suites passed.
2. **Missing `LS_CI=1` in `ci.yml`:**  
   `tools/loopback_smoke.sh` and build scripts source `tools/env.sh` unless `LS_CI=1` is exported. On GitHub runners, `tools/env.sh` sets `PUB_CACHE`, `JAVA_HOME`, and `PATH` to non-existent local `.toolchain` directories.
3. **Redundant & Expensive Matrix App Testing:**  
   `apps/libreshare_app/test` only needs to be run once in a headless environment on `ubuntu-latest`. Running it across 4 matrix jobs consumes unnecessary runner minutes.
4. **Untested Windows Runners:**  
   Windows builds and tests cannot be run locally on Linux development machines (`pwsh` and MSVC are unavailable). In `ci.yml`, the Windows matrix leg does **not** have `continue-on-error: true`. A failure on Windows fails the entire CI pipeline.
5. **Unsupported macOS Target:**  
   `ci.yml` includes `macos-latest` in the `app` matrix, but macOS is best-effort/deferred (spec §15, `HANDOFF.md` section 1), lacks developer tooling, and has no signing certificates configured.

## 4. Proposed YAML Fragments for Missing Jobs

All jobs use:
- Runner: `ubuntu-latest` (except the experimental Windows job on `windows-latest`)
- Flutter: `3.47.9` via `subosito/flutter-action@v2` (channel: `stable`, `cache: true`)
- Environment: `LS_CI: "1"`
- Resilient flags: `continue-on-error: true` on unverified Windows steps

### Fragment 1: `format`
```yaml
  format:
    name: Format Check
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: ${{ env.FLUTTER_VERSION }}
          channel: stable
          cache: true

      - name: Check code formatting
        run: dart format --output=none --set-exit-if-changed .
```

### Fragment 2: `analyze`
```yaml
  analyze:
    name: Static Analysis & Core Hygiene
    runs-on: ubuntu-latest
    timeout-minutes: 15
    steps:
      - uses: actions/checkout@v4

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: ${{ env.FLUTTER_VERSION }}
          channel: stable
          cache: true

      - name: Resolve workspace
        run: dart pub get

      - name: Verify core does not import Flutter
        run: |
          set -u
          if grep -RnE --include='*.dart' "package:flutter|dart:ui" packages/libreshare_core/lib; then
            echo "::error::packages/libreshare_core must not import Flutter"
            exit 1
          fi
          if grep -nE '^[[:space:]]*flutter:|sdk:[[:space:]]*flutter' packages/libreshare_core/pubspec.yaml; then
            echo "::error::packages/libreshare_core/pubspec.yaml must not depend on Flutter"
            exit 1
          fi

      - name: Analyze code with fatal infos
        run: dart analyze --fatal-infos
```

### Fragment 3: `core-tests`

```yaml
  core-tests:
    name: Core Unit & Security Tests
```

### Fragment 7: `linux-build`
```yaml
  linux-build:
    name: Linux Package Build
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4

      - uses: subosito/flutter-action@v2
        with:
          flutter-version: ${{ env.FLUTTER_VERSION }}
          channel: stable
          cache: true

      - name: Install Linux build dependencies
        run: sudo apt-get update && sudo apt-get install -y clang cmake ninja-build pkg-config libgtk-3-dev liblzma-dev xvfb

      - name: Run Linux headless integration tests (if present)
        if: hashFiles('apps/libreshare_app/integration_test/**') != ''
        run: cd apps/libreshare_app && xvfb-run -a flutter test integration_test -d linux

      - name: Package Linux Prototype
        env:
          LS_CI: "1"
        run: tools/package_prototype.sh linux

      - name: Upload Linux artifact
        uses: actions/upload-artifact@v4
        with:
          name: libreshare-linux-x64
          path: dist/prototype/*linux*
          if-no-files-found: error
```

### Fragment 8: `android-build`

```yaml
  android-build:

```

### Fragment 9: `windows-build` (Untested / Experimental)
```yaml
  windows-build:
    name: Windows Package Build (Experimental)
    runs-on: windows-latest
    timeout-minutes: 45
    continue-on-error: true # Note: Windows environment is untested locally; do not block CI

      - uses: actions/checkout@v4

```

## 5. Note on Windows Jobs (Untested)

- **Untested Status:** The project development environment is Linux (Ubuntu 24.04). No Windows machine or `pwsh` toolchain is available locally. Windows builds and CLI runtime behaviors cannot be locally verified.
- **Resilience Strategy:** The Windows workflow fragment specifies `continue-on-error: true` so that regressions or toolchain changes on `windows-latest` runners do not block the primary Linux/Android CI validation gate.

## 6. Full Proposed Architecture (`.github/workflows/ci.yml`)

When ready to update `.github/workflows/ci.yml`, the recommended pipeline DAG is:

```
[ Push / Pull Request ]
   ├── format (Ubuntu)
   ├── analyze (Ubuntu)
   ├── core-tests (Ubuntu)
   ├── cli-tests (Ubuntu)
   ├── app-tests (Ubuntu)
   ├── loopback-smoke (Ubuntu, LS_CI=1)
   └── docker-e2e (Ubuntu, Docker Compose)
         │
         ▼ (requires test jobs green)
   ├── linux-build (Ubuntu)
   ├── android-build (Ubuntu, JDK 17)
   └── windows-build (windows-latest, continue-on-error: true)
```

This ensures fast feedback, isolated job failures, full coverage of the 120+ new security and conformance tests, and separation of app unit testing from packaging.
