### Wave C: adversarial and fuzz tests (NEW test files, red allowed in proofs only)
Write new tests (in `.toolchain/scratch/qa/`, delivered as proposals) for the gaps from waves A/B and for these attack/chaos classes, using in-process fakes and loopback only:
1. Protocol abuse: truncated/oversize/duplicated/out-of-order chunk PUTs, wrong `Content-Length`, lying manifest sizes, negative/huge offsets, duplicate file indices, header injection, unknown JSON fields, wrong major version (426), slowloris, connection-cap flood, replayed session ids, goodbye/bye forgery.
2. Integrity chaos: flip one bit at random chunk/offset (many seeds), truncate at every boundary, kill the receiver at random points (kill -9 of a child process), kill the sender, disk-full simulation (small tmpfs-like limit or throwing writer), read-only destination, file changed during send, file deleted during send.
3. Concurrency: bidirectional simultaneous transfers (FR-17), 10 senders to one receiver, cancel during every state, double accept/reject, engine stop during transfer, restart with stale `.lspart`.
4. Link/NAT/rendezvous/BLE fuzz: share-link parser (random fragments, huge params, duplicate keys, unicode), SSDP/IGD XML (billion-laughs, entity expansion, huge elements, wrong content types), NAT-PMP/PCP packet fuzz, Nostr event fuzz (bad sig, bad kind, bad created_at, huge content), replay, ntfy backend errors, GATT frame fuzz, EID rotation edge (epoch boundary).
5. Property tests (seeded, reproducible): chunker arithmetic, manifest ordering, filename sanitiser idempotence and containment, secret redactor idempotence (never reveals more after redaction), codec round-trips.
6. Cross-platform semantics (simulated): Windows path rules, case-insensitive collisions, trailing dots/spaces, alternate data streams, long paths; Linux names with newlines/control characters.
Every test: OS ports, 3x stable (or a documented seed for the failing case), no sleeps longer than needed, no timing assertions tighter than 3x the observed time.

## 5. How to report a bug (one file per bug: `docs/test-reports/qa/BUG-<NNN>.md`, plus the running `docs/test-reports/qa/INDEX.md`)
```
BUG-NNN  <one-line title>
Severity: S0 data loss/corruption accepted or security bypass | S1 transfer fails or leaks sensitive data in a reachable scenario | S2 wrong behaviour with workaround / misleading security claim | S3 cosmetic, doc, or only in unusual setups
Goal(s) violated: G#, FR/NFR ids
Found by: wave / test / mutation / reading
Reproduce: exact command or test file + name, seed, environment (clone commit state), expected vs actual, exit code, last 10 relevant log lines (no secrets)
Reproduced: N of N runs (>= 3), flake? yes/no (compare with docs/test-reports/flake-analysis.md)
Cause (file:line) and confidence: CONFIRMED (shown by a failing test or debugger-level evidence) | LIKELY | SUSPECTED
Proposed fix: smallest patch as docs/plans/qa-proposals/BUG-NNN/fix.diff (git apply --check -p1 against the CURRENT real tree) or a description
Bug-proof test: docs/plans/qa-proposals/BUG-NNN/proof_test.dart: RED on the current tree, GREEN with fix.diff (show both runs). NEVER put a red test into the real tree's suite.
```
Rules: no duplicates (search INDEX first); no bug without a reproduction; known flakes and known open items are NOT bugs unless you bring new evidence; do not inflate severity; if you are unsure, label SUSPECTED and say what evidence would settle it.
