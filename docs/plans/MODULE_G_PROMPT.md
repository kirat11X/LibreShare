## Working rules (all cards)

1. **Snapshots (Zone A).** Before touching a Zone A file or directory: `rsync -a` a copy into `REPO/.toolchain/snap/g/<card>-before/<same relative path>` (create it; never delete). After the card: `diff -ruN` the snapshot against the tree into `docs/plans/g-proposals/<card>/applied.diff` so the orchestrator can review or revert. A card that ends red twice: **move** (not delete) the files it created into `REPO/.toolchain/scratch/g-rolled-back/<card>/`, restore the touched files from the snapshot with `rsync -a`, write the card into `questions.md` (what you tried, what you read, the options), and take the next card.
2. **Tests first, red first.** A tester writes new test files and shows them red; only then the coder; a different verifier runs 3x flake runs and at least two mutation checks per card. Never edit, delete, skip or weaken an existing test; a needed change goes to `questions.md`.
3. **Real clock.** Every timestamp comes from `date '+%F %T'`.
4. **Heavy runs.** Only through `flock -o /tmp/libreshare-heavy.lock <cmd>`, one at a time for the whole module and for module E, `TMPDIR="$REPO/.toolchain/tmp"`, `--concurrency=1` or `-j 1`. A silence watchdog kills only the test process YOU started after 120 s without output (a hang is a test bug). After an Android build: `gradle --stop`; after any adb use: `adb kill-server`. `lslocks | grep libreshare`: holder `WRITE`, waiter `WRITE*`. The orchestrator also takes this lock for its own gates; a lock held longer than 60 minutes by something you did not start is a HALT condition, never a reason to kill that process.
5. **Ports.** Tests bind fixed ports (53318...). Pick unique ports per run (`53900+`), never run two test processes at once.
6. **Claims.** Every statement in a report has the command and its rc next to it. "Passed" without counts is rejected. Say "not verified" when you did not run it.
7. **Secrets.** Never log or write a PIN, key, token, pairing secret or tunnel URL fragment. Run the two-tier secret scan from module E on every file you created, before reporting.
8. **Decision rules for routine questions (do not stop to ask):** prefer the more conservative option; prefer leaving a test unchanged and asking in `questions.md`; prefer a note over a code change when a change would touch Zone B; prefer parking a card over guessing a protocol detail; when two sources of truth disagree, the spec and `LSP-1.md` win over a plan, and a measured result wins over a hypothesis.
