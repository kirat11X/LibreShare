# Mutation campaign, verified (2026-11-08)

Fresh copy of the CURRENT tree (rsync at campaign start, `.dart_tool` reused; real tree untouched). One mutant at a time, pristine copy kept in `.toolchain/scratch/qa-m/pristine/`, `cmp` after every restore. Every `dart test`/`flutter test` ran under `flock -o /tmp/libreshare-heavy.lock` with `timeout 600` (whole-suite fallback `timeout 1800`). Harness: `.toolchain/scratch/qa-m/harness.py`, mutants: `mutants.py`, per-mutant logs: `logs/Mxx.log`, raw results: `results.json`.

Rules enforced by the harness: target string occurs exactly once (precheck: 0 problems of 134); killer tests must exist and PASS on the unmutated clone (count shown in the table); KILLED only if tests ran and at least one failed (compile errors, load errors, timeouts and "no tests" are ERROR, never KILLED); a SURVIVED mutant triggers the WHOLE suite of the package; a suite failure only counts as KILLED-BY-OTHER if the failing file also fails twice in isolation on the mutant.

Pristine baseline: the whole core suite is 3447 pass / 2 fail. The 2 failures are `ladder_fault_test.dart` "FR-12 tier-1-first" and "every-chunk-on-tier-1", which fail under whole-suite load and pass when the file runs alone (3 more load-flaky files show up randomly in mutant suite runs, e.g. startup_test FR-01, soak_stress, receive_mode_engine). They were not allowed to count as kills.
