# Traceability matrix

Every functional (FR) and non-functional (NFR) requirement traces to the module that implements it, the automated test that proves it, and the increment that delivers it. Seeded from `docs/LIBRESHARE_BUILD_SPEC.md` section 12 ("Traceability seed") and the per-increment acceptance lists; updated at the end of every increment (spec section 12, step "update docs/traceability.md").

**Status values.** `planned` - not started. `inc1-in-progress` - being built in Increment 1. `inc1-done` - the Increment 1 share of the requirement is proven by automated tests that pass (named in the row); a later increment named in the *Increment* column may extend it. `inc2-done` - the Increment 2 share of the requirement is proven by automated tests that pass locally (named in the row); CI has not run them yet. `inc2-core-done` - the headless share (core + CLI) is proven by named passing tests; the app screen, Docker e2e or CI part named in the row is still open. `done` - fully proven by automated tests that pass in CI. `manual` - proven by a documented manual test in `docs/test-reports/`.
**Wording.** Summaries are taken from the spec text. Where the spec names an FR/NFR only by ID in an acceptance list, the summary is inferred from that list and marked `(inferred)`.
**Paths.** Modules are under `packages/libreshare_core/lib/src/` unless stated. Tests are under `packages/libreshare_core/test/` unless stated.
